# Executive Summary We will build a **mobile-first, single-page interactive birthday site** in one `index.html` for Rapunzel. It uses only HTML/CSS/JavaScript (no heavy frameworks) and is hosted on GitHub Pages. The site will feel like an animated story, with **cinematic transitions**, layered parallax, touch-activated particles/lanterns, a 3D-like gift opening, flickable candles, a scrollable “memory room” of photos, an unfolding letter, and a final secret message. Performance is paramount: we rely on CSS transforms and Web Animations (avoid layout thrashing), use feature detection and progressive enhancement, and keep libraries minimal (e.g. Anime.js ~17KB gzipped vs GSAP core ~25KB). User-uploaded photos will be saved in `localStorage` (≈5 MB limit), or optionally a cloud service if cross-device sync is needed. All code and assets live in one file or referenced from CDN, so deployment is simple (push to GitHub Pages and enable it). Key technical approaches (Touch Events API, requestAnimationFrame, IntersectionObserver, etc.) are chosen for smooth mobile experience. The plan below details features, choices, code structure, asset handling, and a deployment checklist. ## Prioritized Features (with complexity, cost, fallback) - **Cinematic Opening Scene:** A full-screen intro with animating Rapunzel-themed artwork (panning, fade-in text). *Complexity:* High (timed CSS keyframes). *Performance:* Medium (CSS-only, GPU-accelerated). *Fallback:* Plain static title if animations disabled. - **Star-Hunt Interaction:** Tap-floating stars to collect (count 5). Stars glow and trigger on-click particles. *Complexity:* Medium. *Performance:* Medium. *Fallback:* If touch absent, stars appear static or you auto-complete. - **Gift Box Opening:** A 3D-looking gift. On tap, the lid slides open (CSS `transform`), a “flash” animation and particles burst out, then transition to next scene. *Complexity:* High. *Performance:* Medium (one CSS animation, one JS trigger). *Fallback:* Simply replace with a “Open” button to reveal next content. - **Cake with Candles:** A stylized cake graphic with three candle elements. Detect swipe or flick gesture to extinguish each flame (remove flame element). Use a subtle “puff” animation when done. *Complexity:* Medium. *Performance:* Low. *Fallback:* Tapping toggles flame on/off without swipe; if no JS, show cake image without interaction. - **Memory Room (Photo Gallery):** A grid of 3 placeholder frames (Rapunzel scenes). Tapping a frame opens a modal with a title and text. A “+” button lets user upload a photo (via ``) which replaces a placeholder and saves base64 in `localStorage`. *Complexity:* Low. *Performance:* Low. *Fallback:* If no JS, show static images/text; uploading disabled (explain “use modern browser”). - **Letter Envelope:** Show an envelope graphic. On tap, animate flap opening (CSS flip). Then reveal a letter (`
` with scrollable text) that types out (char-by-char JS typing). *Complexity:* Medium (CSS transform + JS timing). *Performance:* Low. *Fallback:* Envelope opens instantly, letter text all visible. - **Final World Reveal:** A scene with floating lanterns and stars. The camera “pulls back” (simulated by zoom-out or elements moving slower) to reveal “Happy Birthday Rapunzel” text with a heart animation. *Complexity:* High (multiple layers, parallax). *Performance:* Medium (CSS transforms + `requestAnimationFrame`). *Fallback:* Static final image and message. - **Secret P.S. Message:** A hidden “P.S.” button reveals a locked box. Tapping it plays a quick flash and transitions to a secret congratulatory message. *Complexity:* Low. *Performance:* Low. *Fallback:* No secret if JS off (just final message). Each animation uses GPU-friendly transforms (no layout-triggering changes). We avoid heavy effects (no background-attachment:fixed on mobile) and only add them if the device can handle it (use media queries to disable on low-end phones). ## Recommended Technology - **Core Stack:** Vanilla HTML5/CSS3/JavaScript. We do **not use a build step**; all code (including CSS and JS) is in one file. This fits GitHub Pages (static) and ensures offline use. Use semantic HTML elements and ARIA labels for accessibility (tab order for modals/buttons, etc.). - **CSS:** Use modern features: CSS Grid/Flexbox for layout, `transform: translate3d/scale/rotate` and `opacity` for animations (hardware-accelerated). Use CSS variables for theming (colors/fonts). Include keyframe animations or the Web Animations API for timeline control. Avoid `background-attachment: fixed` on mobile (poor support); simulate parallax by transforming layers on scroll/drag. - **JavaScript:** Minimal “frameworks”. Use ES6+ (modern `querySelector`, `classList`, arrow functions, etc). Key APIs: - **Touch/Pointer Events:** `touchstart`, `touchmove`, `touchend` (or PointerEvents) to detect taps and swipes. Use `preventDefault()` on `touchmove` to stop scrolling during gestures. - **requestAnimationFrame:** For any continuous animations or parallax updates (smooth 60fps). - **IntersectionObserver:** (Optional) to trigger animations when elements scroll into view, though this app is one-page with no real scrolling. - **LocalStorage:** For photo upload persistence. We’ll `readAsDataURL()` from an `` and store strings in `localStorage` (max ~5 MB). Use `try…catch` around `localStorage.setItem()` in case of full quota. - **Web Animations API:** Could use [115†Web Animations] (native JS animations with easing), but CSS keyframes suffice. - **Small Libraries (only if necessary):** We prefer **no libraries** for core interactions. If a tiny helper is needed, consider: | Library | Size gzipped | Pros | Cons | | ---------- | ----------- | ------------------------------- | ------------------------------- | | anime.js | ~17 KB | Lightweight, easy tweening API (CSS + JS) | No built-in scroll trigger features. | | GSAP Core | ~25 KB | Powerful timelines, ScrollTrigger plugin | Larger, complexity overhead. | | Lottie | ~30 KB gz (Lottie core) | For vector animations (JSON) | Requires creating/obtaining Lottie JSON. | | Hammer.js | ~7 KB gz | Gesture detection (tap/swipe) | Additional code; only if needed. | | (none) | 0 KB | Native APIs (recommend this) | Manual coding of animations. | In practice, **plain JS/CSS** is sufficient. (Per Nate Bal, avoid heavy libraries for simple effects.) For example, use CSS `transition-timing-function: cubic-bezier(…)` or `animation-timing-function: ease-out` to mimic the video’s smooth slows and eases. ## Animation Timing & Easing - **Cinematic Transitions:** Use slow ease-in-out or custom cubic-bezier curves. Example: `cubic-bezier(0.42, 0, 0.58, 1)` for smooth acceleration/deceleration. Pan/fade effects ~1–1.5s. - **Particles & Lanterns:** Light floating motion with subtle ease-in-out loops (1–3s repeat). For example, animating a lantern up and down with `animation: translateY(-20px) 5s ease-in-out infinite`. - **Particles/Light Trails:** Quick fade-in (0.3s) and fade-out (0.8s) via CSS. Trigger on `touchmove` using JS and remove after animation end. - **Gift Opening:** Lid transition ~0.7s ease-out plus a brief “burst” (flashing white overlay ~0.3s). - **Candle Flick:** A flick gesture extinguishes with a short puff (0.5s) and flame fading with a “scale up + fade” CSS (like `transform: scale(1.2) opacity 0`). - **Typing Letter:** Use setInterval (25–50ms per character; a longer delay at line breaks) to simulate typing. (The letter content can be stored in a JS string literal.) - **Heart Beat (final):** Use `@keyframes heartbeat` (scale 1↔1.1 over 1–1.5s, infinite, ease-in-out). - **Overall Flow:** Sequence animations so one ends then the next section is shown. Use `setTimeout` or `animationend` callbacks to chain screens. (Example: after gift lid finishes, flash and `setTimeout(showNextScreen, 400)`.) These timings will be fine-tuned by observing the reference video’s pace (once provided), but the above gives a benchmark. We rely on CSS easing for hardware-accelerated performance and minimal JS timers. ## Touch & Interaction Mapping User interactions (primarily taps and swipes) control the flow: - **Tap Star:** `(touchend)` on a star element increments count, plays sparkle effect, and moves star to next position. - **Tap Gift Box:** `touchstart`/`click` on box runs `openGift()`: add `.open` class to animate lid up, then triggers screen change. - **Swipe Candle:** Detect `touchstart` then `touchend` and calculate vertical movement. If motion is upward and speed above threshold, consider it a “blow-out” and remove flame (add class `.off`). Otherwise, if just a tap, do nothing. Use a short touch-move tolerance to distinguish flick from static tap. - **Tap Memory Frame:** On `touchstart`, show modal overlay with enlarged photo. Modal close via a “Close” button or tap outside. - **Upload Photo:** `` change event reads `FileReader` result and saves to `localStorage`. We throttle size (limit 3 photos, each must fit localStorage). - **Envelope Drag:** Optionally allow dragging flap open (via CSS rotation). Simpler: on tap, add `.open` class and show letter. - **Final Secret Box:** Tap the locked box (like gift) toggles secret screen. Touch events fire differently than mouse; mobile scrolling is via touch gestures. We’ll call `e.preventDefault()` on touchmove to avoid unwanted scroll. All clickable items also respond to `pointerdown`/`pointerup` or `click` for compatibility (Pointer Events API). The MDN Touch Events guide explains using `touchstart`/`touchmove`/`touchend` to track fingers, which we’ll use in custom handlers. Key is to write minimal logic (no heavy libraries) and provide passive fallbacks if JS is off (e.g. static “continue” button). ## Asset & Image Handling - **Placeholders:** Use Rapunzel-related **public-domain or CC images** for frames (Wikimedia Commons has Parade photos under CC BY 2.0, though caution is noted that they depict a copyrighted character). We **should not use official Disney art without permission**. Instead, include *generic fantasy-style images* or prompt the user to supply their own art or license-free illustrations. In code, we’ll have placeholder ``, etc., which the developer can replace. - **Data URIs for Simple Assets:** For very small graphics (e.g. icons, sparkles), consider embedding as base64 data URIs to keep one file. - **LocalStorage for User Photos:** When the user taps “+” and selects an image, we convert it with `FileReader.readAsDataURL()`, then `localStorage.setItem("photo0", dataURL)`. On load, check `localStorage` keys “photo0..2” and populate frames. (MDN notes Web Storage max ~10 MiB total, so we can safely fit a couple of small JPG/PNG photos per frame.) Wrap storage calls in `try...catch` to handle `QuotaExceededError` if needed. - **Shared Photo Storage (Optional):** | Option | Pros | Cons | |-----------------------|----------------------------------------------|-------------------------------------------| | **Static Repo Files** | Easiest; all visitors see same images. | No user uploads; needs redeploy for new images. | | **`localStorage`** | Instant, offline-capable, per-device. | Limited (~5 MB); not synced; only in same browser. | | **Firebase Storage** | Cloud sync; can auth users; secure. | Requires SDK (adds ~7–10KB gz), setup, possible costs beyond free tier. | | **Supabase Storage** | Similar to Firebase; supports large files. | Requires account, network; somewhat complex. | For simplicity and static site constraints, we use **`localStorage`** (no extra libs, works offline). We inform users that images are stored locally, so another person on a different device won’t see them unless uploaded to a backend. ## Testing & Deployment

- **Test on devices:** Verify on real phones/tablets that **touch gestures** work smoothly and no jank (aim for 60fps). Use Chrome DevTools (mobile emulation) and actual iOS/Android. Check that all screens show/hide correctly and `localStorage` saves images.  
- **Progressive Enhancement:** With JavaScript disabled (or in a very old browser), ensure the core message is still accessible. For example, each screen could show a simple fallback message or continue button. (At minimum, the final “Happy Birthday” should always display.)  
- **Performance:** Run Lighthouse or WebPageTest to check that the site loads quickly (it should, as it's a single small HTML with no external libs). Ensure the total `index.html` size stays small (< 200KB gz) by compressing images and inlining only tiny assets. Use `requestAnimationFrame` loops sparingly to avoid battery drain. Remove any unused code.  
- **Accessibility:** Ensure color contrast is OK, text readable, and interactive elements are large enough (44px tap targets). Use `aria-label` on buttons if needed.  
- **Deployment:** Once ready, commit `index.html` (and any non-inlined assets) to a GitHub repo. In GitHub settings → Pages, select the main branch and `/ (root)` as source. Wait a few minutes and then visit `https://.github.io//`. The site will be served entirely as static files.  
- **Checklist:**  
  - [ ] Index.html is in root and is the only file needed (besides images, fonts).  
  - [ ] All `console.log`/debug code removed.  
  - [ ] Tested `localStorage` image upload (select a few photos, refresh page, and see them reappear).  
  - [ ] Animations run on low-power mode (reduce to 30fps if needed, or provide CSS prefers-reduced-motion fallback).  
  - [ ] No third-party cookies or tracking (it’s a personal gift site).  
  - [ ] If internet images used (CDN), ensure `https://` links to avoid “mixed content”.  

Following this plan will yield a **fully interactive, Rapunzel-themed birthday website** that captures the cinematic feel of the reference video, runs efficiently on mobile, and can be easily hosted on GitHub Pages. All content resides in one file for simplicity, and the design gracefully degrades if needed.
