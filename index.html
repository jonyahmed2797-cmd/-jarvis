# Executive Summary An **interactive birthday website** (“A Little World Made For You — Rapunzel”) will be built as a **single HTML file** using only HTML, CSS, and JS (no heavy frameworks). The site will be **mobile-first** and performance-optimized, following 2026 design best practices. Key principles: use **transform/opacity animations** (smooth on mobile), lean code, optimized images, and avoid heavy 3D/WebGL. We will implement a short “mini-story” flow: **mystery star → chase/tap → open gift → blow candles → memory room with images → handwritten letter → final reveal → secret P.S.**. All interactions use simple CSS transitions and JS event handlers; touch/tap gestures work on mobile. Assets will be **public-domain or CC0 images** (no Disney-owned art), embedded via safe URLs. Accessibility and inclusion are considered (alt text for images, appropriate tap targets, reduced-motion option). We’ll use progressive enhancement/fallbacks (e.g. ensure basic content shows if JS is off, avoid non-essential effects for older browsers). The result is a **lightweight, single-page birthday site** deployable on GitHub Pages (no server needed). # Features Checklist (mobile-first, interactive, performance) 1. **Setup & Structure:** Use a single `index.html`. Include `` for mobile. Use semantic sections (intro, star chase, gift, candles, memories, letter, final, secret). 2. **Mystery Opening:** Dark fullscreen with a tiny glowing dot → animated into a star. Fade-in text “I made something for you. …But you have to find it.” Show **Start ✨** button. (JS toggles section visibility.) 3. **Follow the Light:** A glowing star moves randomly on screen (using `transform` transitions). Tapping the star progresses steps. Each tap adds layers (more stars, then moon 🌙, floating particles, lanterns) via CSS classes/transforms. This builds suspense with micro-animations (using only opacity/translate for performance). After 5 taps, reveal text “There you are. ❤️”. 4. **Mystery Box:** Show a glowing gift box centered. On tap, play a CSS burst (scale/opacity) and swap it with a birthday cake image 🍰 (no candles yet). Display text “I have something for you…”. (Ensure animations use `transform`/`opacity` and `will-change` hints for GPU acceleration.) 5. **Candle Wishing:** Sequentially show 3 candles on the cake. Prompt “Make a wish.” Tapping each candle triggers a short flame→smoke fade-out animation (using CSS keyframes: scale/opacity). After all 3 are blown (flames out), play a small confetti burst (particles and celebration sound). This uses lightweight CSS animations (no canvas). 6. **Memory Room:** Transition to a “photo room” background. Display three tappable photo frames (positions with a bit of parallax/depth effect on tilt) containing Rapunzel-themed images. Use the 3 chosen CC0 images (see **Image Assets** below). Each frame has a short caption. Tapping a frame enlarges it slightly (simple `transform: scale()` CSS) or could simply fade in a larger view. (We’ll ensure readable alt-text like “Memory: That smile…” for accessibility.) 7. **Handwritten Letter:** After memories, clear the screen to a blank page with an envelope icon. Tapping opens it to reveal a multiline letter in a handwritten font. Use a JS *typewriter effect*: add one character at a time (with a small delay) to simulate writing. The letter should be personal (sample text provided). Make sure text is large enough for mobile and has good contrast (Figma notes high-contrast palettes and voice/keyboard support are trending). 8. **Final Reveal:** After the letter, slowly zoom out (scale transform) to show the whole “birthday world” (moon, stars, lanterns, cake, photos, hearts) as a cohesive scene. Then fade in final text: **“Happy Birthday, Rapunzel.”** Pause, then show “I hope this little world made you smile. Because you deserve a beautiful year ahead. ❤️”. 9. **Secret P.S.:** Finally reveal a **“P.S.”** button. On tap, show: “You thought that was everything? 👀” and reveal a second surprise (e.g. a second gift or favorite photo/video). This uses the same tap-to-open animation. This twist is small and uses another CSS burst or just fades in an extra message. **Mobile Performance:** All animations use `transform` and `opacity` (GPU-accelerated). Avoid layout-triggering animations (no margin/width animating). Limit asset size: compress images (file sizes <100KB if possible). Use `will-change` sparingly on animating elements. Lazy-load non-critical images (e.g. memory photos can load after gift animation). No external libraries; all code and CSS are inline. Keep CSS under ~20KB, JS under ~30KB. No ads or tracking – all static. **Accessibility:** Every image has meaningful `alt` text (e.g. “Child dressed as fairy princess” for image of Rapunzel-themed girl). Buttons/tappable elements have large enough hit areas (at least 48×48px). Support keyboard: the “Start”, “Make a wish”, and “P.S.” can be activated by Enter key (via `button` or `tabindex`). Include `aria-labels` on decorative hearts/particles if needed (or mark them `aria-hidden`). Provide a “prefers-reduced-motion” CSS media query fallback: if set, skip auto-animations and just show final states (this can be done by disabling CSS animations). High-contrast color scheme ensures text is legible. **Progressive Enhancement & Fallbacks:** The core message (“Happy Birthday, Rapunzel”) and images should display even if JS fails. We can put a basic greeting in the HTML body as default. All fancy interactions (star chase, typing) degrade gracefully if scripts disabled. (For example, sections besides intro are hidden by default; if JS is off, ensure some final message is still visible.) Use modern CSS, but include vendor prefixes or simpler properties for older browsers. Avoid features like CSS custom properties in critical layouts (older browsers fall back to defaults). **Deployment (GitHub Pages):** Simply push the final `index.html` to a GitHub repository (set to use GitHub Pages). Since it’s static and single-file, nothing else is needed. Ensure `` is correct if used. No server, no CORS issues.
